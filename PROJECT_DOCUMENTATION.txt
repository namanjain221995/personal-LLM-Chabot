================================================================================
NAMAN CHATBOT PROJECT - COMPLETE DOCUMENTATION
Salesforce App with Zoom Recording Portal & Job Requirement Management
================================================================================

PROJECT OVERVIEW:
This is a Salesforce application that manages:
1. Zoom Recording Portal - Secure access to Zoom recordings stored in AWS S3
2. Job Requirement Management - REST API to fetch job listings
3. Access Control & Logging - Track user access to recordings and portal activity
4. Department Management - Organize recordings by department with permission sets

Technology Stack:
- Salesforce Apex (Backend)
- Lightning Web Components (LWC) (Frontend UI)
- AWS S3 (File Storage)
- Salesforce Flows (Automation)

CUSTOM OBJECT 1: Zoom_Recording_Access_Log__c
Description: Audit log for tracking all user access to the Zoom Recording Portal
Purpose: Security and compliance tracking - logs every login, file access, and portal activity

Fields:
  - User__c (Lookup to User)
    Type: Lookup
    Purpose: References the user who performed the action
    
  - Department__c (Lookup to Zoom_Recording_Department__c)
    Type: Lookup
    Purpose: Department associated with the accessed recording/folder
    
  - Event_Type__c (Picklist)
    Type: Picklist
    Allowed Values:
      * View - User viewed a recording
      * Download - User downloaded a file
      * Access_Denied - User attempted unauthorized access
      * Login - User logged into portal
      * Portal_Access - User accessed portal interface
      * File_Access - User accessed a specific file
      * Login_Success - Successful login event
      * Login_Failed - Failed login attempt
      * Logout - User logout event
      * Screen_Recording_Attempt - DevTools/inspect attempt detected
    Purpose: Categorizes the type of action performed
    
  - Event_Timestamp__c (DateTime)
    Type: DateTime
    Purpose: When the event occurred
    
  - Status__c (Picklist)
    Type: Picklist
    Allowed Values:
      * Success - Operation successful
      * Failed - Operation failed
      * Blocked - Access blocked/denied
    Purpose: Result status of the access attempt
    
  - Error_Message__c (Text)
    Type: Long Text Area
    Purpose: Stores error details or additional context
    
  - File_Key__c (Text)
    Type: Text (255 chars)
    Purpose: S3 file path/key of accessed file
    
  - File_Name__c (Text)
    Type: Text (255 chars)
    Purpose: Human-readable name of accessed file
    
  - IP_Address__c (Text)
    Type: Text (45 chars)
    Purpose: IP address of the user making the request
    
  - User_Agent__c (Text)
    Type: Text (255 chars)
    Purpose: Browser/client user agent string
    
  - Opened_At__c (DateTime)
    Type: DateTime
    Purpose: When file was opened (if applicable)
    
  - Opened_By__c (Lookup to User)
    Type: Lookup
    Purpose: User who opened the file
    
  - Recording_Link__c (URL)
    Type: URL
    Purpose: Link to the recording
    
  - Record_Id__c (Text)
    Type: Text (18 chars)
    Purpose: Related Salesforce record ID
    
  - Record_Name__c (Text)
    Type: Text (255 chars)
    Purpose: Related record name
    
  - Source_Object__c (Text)
    Type: Picklist
    Purpose: Type of source object (Interview, Job Requirement, etc.)
    
  - Source__c (Text)
    Type: Text
    Purpose: Source/origin of the access request
    
  - Interview__c (Lookup to Interview__c)
    Type: Lookup
    Purpose: Related interview if any
    
  - Session__c (Text)
    Type: Text
    Purpose: Session identifier for grouping related events

CLASS 1: ZoomRecordingS3Service
File: force-app/main/default/classes/ZoomRecordingS3Service.cls
Purpose: Core AWS S3 integration for managing files and generating signed URLs
Sharing: public with sharing
Dependencies: ZoomRecordingPortalConfig

CONSTANTS:
  - NAMED_CREDENTIAL = 'callout:AWS_S3_Named_Credential' (Named Credential for AWS auth)
  - AWS_REGION = 'us-east-1' (Default AWS region)
  - S3_SERVICE = 's3' (AWS service identifier)

Key Methods:
  
  1. listFiles(String folderPath, Integer maxKeys) → List<S3FileInfo>
     Purpose: List all files in an S3 folder
     Parameters:
       - folderPath: S3 folder path (e.g., "sales/2024/")
       - maxKeys: Max results per page (default 100, max 1000)
     Returns: List of S3FileInfo objects with file metadata
     Used by: Portal UI to display file list
  
  2. listFilesPage(String folderPath, String continuationToken) → S3PageResult
     Purpose: Paginated file listing with continuation tokens
     Parameters:
       - folderPath: S3 folder path
       - continuationToken: Token for fetching next page
     Returns: S3PageResult with files list and nextToken
     Used by: Portal for handling large folders
  
  3. listFolders(String prefix) → List<String>
     Purpose: List direct subfolders using S3 delimiter
     Parameters:
       - prefix: Parent folder path
     Returns: List of folder paths
     Used by: Navigation tree, folder browser
  
  4. generateSignedUrl(String s3Key) → String
     Purpose: Generate AWS Signature V4 pre-signed URL for playback
     Parameters:
       - s3Key: Full path to S3 file (e.g., "sales/video.mp4")
     Returns: HTTPS URL valid for configured expiry time
     Used by: Video player to access files without AWS credentials
  
  5. buildSignedUrl(...) → String [PRIVATE]
     Purpose: Internal implementation of AWS V4 signature generation
     Details:
       - Creates canonical request following AWS V4 spec
       - Signs with HMAC-SHA256 using secret key
       - Includes X-Amz-* headers in URL parameters
  
  6. getFileInfo(String s3Key) → S3FileInfo
     Purpose: Get metadata about specific file via HEAD request
     Parameters:
       - s3Key: File path
     Returns: S3FileInfo with size, content type, last modified, ETag
     Used by: File details, size validation
  
  7. parseListResponse(String xmlBody) → List<S3FileInfo> [PRIVATE]
     Purpose: Parse XML from S3 ListObjectsV2 API response
  
  8. parseFolderResponse(String xmlBody) → List<String> [PRIVATE]
     Purpose: Parse CommonPrefixes from S3 for folder listing
  
  9. parseNextContinuationToken(String xmlBody) → String [PRIVATE]
     Purpose: Extract continuation token for pagination

Inner Classes/DTOs:
  - S3FileInfo: Contains file metadata
    * s3Key: Full S3 path
    * fileName: Just the filename
    * size: File size in bytes
    * contentType: MIME type
    * lastModified: ISO timestamp
    * etag: S3 ETag hash
    
  - S3PageResult: Pagination wrapper
    * files: List<S3FileInfo>
    * nextToken: Continuation token for next page
    
  - S3Exception: Custom exception for S3 errors

CLASS 11: JobRequirementRestService
File: force-app/main/default/classes/JobRequirementRestService.cls
Purpose: REST API endpoint for fetching Job Requirement records
Endpoint: /services/apexrest/jobRequirements/
Method: GET (HTTP GET)

Query Parameters (all optional):
  - pageNumber: 1-based page index (default 1)
  - pageSize: Records per page (default 20, max 200)
  - jobStatus: Filter by Job_Status__c
  - employmentType: Filter by Employment_Type__c
  - priority: Filter by Priority__c
  - workMode: Filter by Work_Mode__c
  - location: LIKE filter on Location__c
  - searchTerm: LIKE filter on Job_Title__c
  - clientAccountId: Filter by Client_Account__c

Filtering Rules:
  - Only returns records where Website_Status__c = "Published"
  - Excludes overdue jobs (SLA_Status__c != "Overdue")
  - Forced Job_Status__c to "Open" (website policy)
  - Results ordered by CreatedDate DESC

Response:
  - Returns JSON wrapped in JobResponse DTO
  - Includes pagination metadata
  - Includes total record count for frontend pagination

Key Methods:
  
  1. getJobRequirements() [HttpGet, Global]
     Purpose: Handle GET requests to endpoint
     Returns: JobResponse with jobs list + metadata

Helper Methods:

  - getFieldList() → String

  - addEqualsFilter(...) [PRIVATE]

  - addLikeFilter(...) [PRIVATE]
    Purpose: Add LIKE WHERE condition
    
  - parsePositiveInt(...) → Integer
    Purpose: Parse integer with default/min value
    
  - extractRecordKey(RestRequest req) → String
    Purpose: Get ID from URL path (/jobRequirements/a03xx)

Inner Classes:
  - JobResponse: API response wrapper
    * jobs: List<JobDTO>
    * totalRecords: Total count for pagination
    * pageSize: Results per page
    * pageNumber: Current page
    * totalPages: Calculated from count/pageSize

LWC COMPONENT 4: zoomRecordingVideoPlayer
File: force-app/main/default/lwc/zoomRecordingVideoPlayer/
Purpose: Secure video playback with anti-screen-recording protection
Sharing: Nested under Portal component

API Properties (@api):
  - file (Object): File to play {s3Key, fileName, size, mimeType}
  - departmentName (String): Department of file

Tracked Properties (@track):
  - signedUrl (String): S3 signed URL for playback
  - transcriptText (String): VTT subtitle content
  - isLoading (Boolean): Loading video URL

  - jsonRecords (Array): Parsed JSON array
  - jsonFields (Array): Column headers for JSON table
  - isScreenBlocked (Boolean): DevTools detected - playback blocked

Anti-Screen-Recording Features:

  1. Detection Mechanism:
     - Monitors keyboard combinations (Meta+Shift, Win+G, Win+Alt+R, Ctrl+Shift+S)
     - Watches for Inspect Element activation
     - Detects getDisplayMedia() calls (screen capture)
     - Monitors DevTools focus
  
  2. Detection Methods:
     - Key combination tracking
     - Visibility API (tab hidden)
     - DevTools open detection
     - Screen recording API interception
  
  3. Response When Violation Detected:
     - Freezes video to black
     - Disables all controls
     - Shows "Access Blocked" message
     - Stores violation marker in sessionStorage (30 min TTL)
     - Logs attempt via logScreenRecordingAttempt()
     - Sends email to admin permission set
  
  4. Violation Recovery:
     - Portal reloads in BLOCKED state
     - Persists 30 minutes
     - After 30 min → can navigate away normally
     - Auto-recovery without admin intervention

Key Methods:
  
  1. connectedCallback()
     Purpose: Initialize player
     Actions:
       - Detect OS (Windows/Mac)
       - Set up keyboard/mouse/visibility listeners
       - Load signed URL for video
       - Check for prior violations
       - Restore blocked state if needed
  
  2. _setupKeyboardGuard()
     Purpose: Intercept suspicious key combinations
     Monitors:
       - Meta+Shift held >30ms (might be inspecting)
       - Win+G (Windows game bar)
       - Win+Alt+R (Windows screen record)
       - Ctrl+Shift+S (Windows screenshot)
       - Cmd+Shift+3/4 (Mac screenshots)
       - Dev tools open detection
  
  3. _loadSignedUrl()
     Purpose: Get playable URL from S3
     Apex Call: getSignedUrl(s3Key)
     Result: HTTPS URL valid for ~8 hours
     Sets: this.signedUrl → video src
  
  4. _loadTranscript()
     Purpose: Load .vtt subtitle file
     Apex Call: getTranscriptText(s3Key)
     Result: VTT format text
     Displays: As subtitles in video player
  
  5. _loadJson()
     Purpose: Parse and display JSON file
     Supports:
       - Array of objects → table format
       - Single object → key-value pairs
       - Raw JSON → text format
  
  6. handleDownload()
     Purpose: Allow user to download file locally
     For .txt: Direct download
     For .vtt: Download as .vtt
     For .json: Download as .json
     Logs: logFileAccess() for audit trail
  
  7. _violationDetected()
     Purpose: Handle screen recording attempt
     Actions:
       - Set isScreenBlocked = true
       - Store violation in sessionStorage
       - Log attempt with timestamp
       - Send email notification
       - Clear video URL
       - Disable all playback controls
  
  8. handleBack()
     Purpose: Return to file browser
     Event Dispatch: 'back' event
     Parent Response: Portal restores file browser
  
  9. handleHome()
     Purpose: Return to dashboard
     Event Dispatch: 'home' event
     Parent Response: Portal switches to dashboard

Security Features:
  - Video URL never passed to untrusted sources
  - S3 signed URLs expire after 8 hours
  - DevTools/Inspector blocks playback
  - Screen recording APIs intercepted
  - All access attempts logged with IP/user agent
  - Admin notified of violations

Supported File Types:
  - .mp4: HTML5 video (primary)

  - .mkv: Matroska format (browser dependent)

FLOW 2: B2B_Jr_update_submission_counts
File: force-app/main/default/flows/B2B_Jr_update_submission_counts.flow-meta.xml
Trigger: Record-triggered (After Create, After Update) on Job_Submission__c
Purpose: Denormalize submission counts to Job Requirement and Lead for reporting
Sharing: System/Process

Flow Type: Autolaunched Flow (Record-Triggered)
Trigger Event: After Create, After Update
Entry Conditions:
  - Status__c changes to certain values
  - Related Job Requirement exists

Variables Used:
  - varJRIds (Collection): List of Job Requirement IDs
  - varTotal (Number): Total submission count
  - varClient (Number): Client submission count
  - varLeadApps (Number): Lead application count
  - varCountSkipped (Boolean): Error flag for fault handling

Collection Loop Blocks:
  1. Loop_JR_Ids
     Purpose: Iterate through Job Requirements related to triggering submission
     Loop Type: Collection loop
     Actions per iteration:
       - Fetch this JR's submissions
       - Count total submissions
       - Count by submission source (client/lead)

  2. Loop_Subs
     Purpose: Iterate through submissions for each JR
     For each submission:
       - Check if from client (client_lead__c != null)
       - If yes: increment client count
       - Always: increment total count

  3. Loop_LeadSubs
     Purpose: Iterate through submissions by same lead
     Counts: Total applications for the lead
     Used for: Lead-level reporting

Assignment Blocks:
  1. asn_AddJRId
     Action: Add JR ID to varJRIds collection
     Used By: Query loop to know which JRs to update

  2. asn_IncTotal
     Action: varTotal += 1.0
     For: Total submission counter

  3. asn_IncClient
     Action: varClient += 1.0
     Condition: Submission from client lead
     For: Client-specific submission counter

  4. asn_IncLeadApps
     Action: varLeadApps += 1.0
     Condition: Submission from Lead
     For: Lead-level application counter

  5. Handle_Count_Fault
     Action: Set varCountSkipped = true
     Reason: If count update fails (data validation issue)
     Effect: Lets record save even if count update fails

Decision Blocks:
  1. dec_IsClientSub
     Condition: Submission.Source__c = 'Client'
     True: Increment client count
     False: Skip (not a client submission)

  2. dec_HasClientLead
     Condition: Job_Requirement.Client_Lead__c != null
     True: Roll up counts to lead
     False: Skip lead roll-up

Update Record Actions:
  1. Update Job Requirement Counts
     Record: Job_Requirement__c
     Fields to Update:
       - Submission_Count__c = varTotal
       - Client_Submission_Count__c = varClient
       - Last_Submission_Date__c = NOW()
     Fault Handler: Handle_Count_Fault (skip error, continue)

  2. Update Lead Application Count (if applicable)
     Record: Lead (Client_Lead__c)
     Fields to Update:
       - Applications__c = varLeadApps
       - Last_Application_Date__c = NOW()

Flow Performance:
  - Runs synchronously on record create/update
  - Should complete within 1-2 seconds
  - Fault handlers prevent cascading failures
  - Bypasses if JR has data validation issues

SECTION 6: SECURITY & ACCESS CONTROL
================================================================================

PERMISSION MODEL:

Level 1: Permission Sets
  - Zoom_Recording_Admin_Access: Full admin access
  - Zoom_Recording_User_Access: Basic user access
  - [Custom department-specific sets]

Level 2: Folder Mappings
  - Zoom_Recording_User_Folder_Map__c
  - Grants access to specific S3 folder paths
  - Can be granted/revoked independently

Level 3: File Type Restrictions
  - Only certain extensions allowed (.mp4, .vtt, .txt, etc.)
  - Blocked folders for non-admins (docs, llm)
  - JSON files restricted by department

Level 4: Department Boundaries
  - Departments linked to folders
  - Permission sets control department visibility
  - Admin can see all departments

ACCESS CONTROL LOGIC:

For File Access:
  1. User is Admin?
     → Yes: Access granted (see all)
     → No: Check step 2
  
  2. User has folder mapping for this folder?
     → Yes: Check step 3
     → No: Access denied
  
  3. File type is allowed?
     → Yes: Check step 4
     → No: Access denied
  
  4. File is not in blocked folder?
     → Yes: Grant access, generate signed URL
     → No: Access denied

Logging & Audit:
  - Every access logged to Zoom_Recording_Access_Log__c
  - IP address and user agent captured
  - Event type categorized
  - Backed up to S3 for long-term retention
  - Email alert to admin permission set on certain events

SIGNED URL GENERATION:
  - V4 algorithm creates time-limited HTTPS URLs
  - Default expiry: 480 minutes (8 hours)
  - Includes X-Amz-Signature header
  - Valid for specific object only
  - Cannot be modified without invalidating signature

API OPERATIONS:
  1. ListObjectsV2: List files/folders (with pagination)
  2. HEAD: Get file metadata
  3. GET: Generate signed URLs (no actual download from Apex)
  4. PUT: Upload backups (logs as JSON)

SECTION 8: CONFIGURATION & SETUP GUIDE
================================================================================

INITIAL SETUP STEPS:

1. Create AWS S3 Bucket
   - Bucket name: your-zoom-recordings
   - Region: us-east-1 (or chosen region)
   - Enable versioning (recommended)
   - Create root folders for departments

2. Create AWS IAM User
   - Permissions: S3 ListBucket, GetObject, PutObject
   - Generate access key + secret key
   - Keep credentials secure

3. Create Salesforce Named Credential
   Path: Setup → Security → Named Credentials
   - Name: AWS_S3_Named_Credential
   - URL: https://[bucket].s3.[region].amazonaws.com
   - Scheme: AWS Signature Version 4

4. Create Custom Metadata Record
   Path: Setup → Custom Metadata Types → Zoom Portal Config
   - Create record with all configuration values
   - Set Is_Active__c = true

5. Create Permission Sets
   - Zoom_Recording_Admin_Access: Full access
   - Zoom_Recording_User_Access: Basic user access
   - Additional department-specific sets as needed

6. Grant Permissions
   - Assign admin permission set to portal admins
   - Assign user permission set to regular users
   - Create folder mappings for granular access

7. Initialize Departments
   - Portal calls ZoomRecordingDeptAutoSync on first load
   - Automatically creates Department records from S3 root folders
   - Can manually create/edit departments as needed

CONFIGURATION FIELDS EXPLAINED:

S3_Bucket_Name__c
  What: AWS S3 bucket name
  Example: "my-company-recordings"
  Impact: All file operations use this bucket

AWS_Region__c
  What: AWS region code
  Example: "us-east-1"
  Impact: Affects S3 endpoint URL and signatures

AWS_Access_Key__c
  What: AWS IAM access key
  Security: Keep in metadata encrypted field
  Impact: Required for S3 operations

AWS_Secret_Key__c
  What: AWS IAM secret key
  Security: Keep in metadata encrypted field
  Impact: Used for signing URLs

Site_Title__c
  What: Portal title in UI header
  Example: "Zoom Recording Portal"
  Impact: Shows to all users

Top_Notice__c
  What: Banner message to all users
  Example: "Portal maintenance 5/1 - 5/2"
  Impact: Displays at top of portal

Signed_URL_Expiry_Minutes__c
  What: How long generated URLs are valid
  Example: 480 (8 hours)
  Impact: Users can view files for this duration
  Note: Longer = more flexible, shorter = more secure

Allowed_File_Extensions__c
  What: Comma-separated file extensions
  Example: "mp4,vtt,txt,m4a"
  Impact: Only these file types accessible to users

COMMON ISSUES & SOLUTIONS:

Issue: "No active Zoom Portal Config found"
  Solution:
    - Navigate to Setup → Custom Metadata Types → Zoom Portal Config
    - Create a record with all required fields
    - Set Is_Active__c = true
    - Refresh portal

Issue: "S3 list failed: 403"
  Solution:
    - Check AWS credentials (access key, secret key)
    - Verify IAM user has ListBucket permission
    - Check bucket name and region are correct
    - Verify bucket exists in AWS console

Issue: User can't access files
  Solution:
    - Check user has Zoom_Recording_User_Access permission set
    - Verify Zoom_Recording_User_Folder_Map__c record exists
    - Check folder path matches S3 path exactly
    - Verify Is_Active__c = true on mapping
    - Check file extension in allowed list

Issue: Videos won't play
  Solution:
    - Verify file is valid MP4 (not corrupted)
    - Check file extension is in Allowed_File_Extensions__c
    - Verify S3 signed URL generated (check browser dev tools)
    - Check browser supports video codec
    - Verify file size < 5GB (browser memory limit)

Issue: Logs not appearing in access log view
  Solution:
    - Check portal_access events logged (check record creation)
    - Verify user has file_access permission
    - Check date range filter in log viewer
    - Verify Zoom_Recording_Access_Log__c records created
    - Check S3 backup is not failing

Issue: Slow file browsing with large folder
  Solution:
    - Pagination handles up to 1000 files per request
    - Load next page button should appear
    - Consider organizing files into subfolders
    - Increase maxKeys if needed

SECTION 12: PERFORMANCE & OPTIMIZATION NOTES
================================================================================

KNOWN PERFORMANCE CONSIDERATIONS:

1. Large Folder Browsing
   - S3 ListObjectsV2 returns max 1000 items per request
   - Portal uses pagination for larger folders
   - Each request ~500ms to S3 + ~1000ms to parse XML + ~2000ms DOM update
   - Total: ~3.5 seconds per page load

2. Access Log Queries
   - With millions of log records, filter by date range first
   - Date range + event type filtering is most efficient
   - User search does 4 SOQL queries (may be slow with large user base)

3. Signed URL Generation
   - AWS V4 signing ~100-200ms per URL
   - Batch operations when possible
   - Cache URLs in LWC if same file accessed multiple times

4. S3 Backup of Logs
   - Async (Queueable) for 5-30 sec delay
   - Sync for immediate but slower (1-2 sec)
   - Groups logs by date and category before upload

OPTIMIZATION TIPS:

1. Use Folder Mappings for Granular Access
   - Instead of permission sets, use folder maps
   - Faster lookup than permission set query

2. Keep Log Records Clean
   - Archive old logs to S3 monthly
   - Delete Salesforce records after backup confirmed
   - Maintain <50MB of log records in database

3. Cache Configuration
   - ZoomRecordingPortalConfig caches config in static variable
   - Valid for entire request
   - Caches permission sets in ZoomRecordingAccessService

4. Batch Operations
   - Use Platform Event for large numbers of logs
   - Queueable jobs for async processing
   - Avoid synchronous processing of >100 records

5. S3 Performance
   - Use CloudFront CDN for served files (future)
   - Enable S3 Transfer Acceleration if needed
   - Monitor AWS S3 request rates (quota: 3,500 PUT/POST per sec)

GLOSSARY OF KEY TERMS
================================================================================

Admin: User with Zoom_Recording_Admin_Access permission set
  → Can access all folders/files regardless of mappings

Department: Grouping of recordings by business unit
  → Each department has S3 folder and permission set
  → Linked to one or more users via mappings

Folder Mapping: Zoom_Recording_User_Folder_Map__c record
  → Grants specific user access to specific S3 folder path
  → Can be granted/revoked independently

Permission Set: Salesforce object controlling feature access
  → Zoom_Recording_Admin_Access: admin features
  → Zoom_Recording_User_Access: basic user features

Signed URL: HTTPS URL with embedded cryptographic signature
  → Grants temporary access to S3 object
  → Expires after configured time
  → Cannot be modified without invalidating

Access Log: Zoom_Recording_Access_Log__c record
  → Records every user action (login, file view, access denied, etc.)
  → Includes IP, user agent, timestamp
  → Backed up to S3 as JSON for analytics

Event Type: Category of access log entry
  → Login_Success, File_Access, Access_Denied, etc.
  → Used for filtering and analytics

S3 Bucket: AWS Simple Storage Service container
  → Holds all recording files and backup logs
  → Organized by department folders

Continuation Token: Pagination token from S3 API
  → Used to fetch next page of results
  → Returned when results > 1000 and IsTruncated=true

Canary Deployment: Testing deployment with subset of users
  → Not currently implemented (suggested future)
  → Would allow gradual rollout of new features
