### How is ownership enforced?

VERIFIED: at one choke point. main.py emit() intercepts every 'meta' event and calls authn_store.bind_report(filename, viewer, conversation_id) for each report_files entry; GET /reports/{filename} requires a session, sanitises the name, looks up report_owner and returns an identical 404 for not-owner and missing. GET /reports lists the caller's rows intersected with disk. Admin download is audited via Cap.WORKSPACE_CONTENT_READ. Bootstrap adopts every unbound on-disk file for the first super-admin. Consequences: a file written but not advertised (crash before meta) is unowned and 404s for everyone; a file produced outside a /chat turn (background job) has no owner unless bound explicitly; first advertiser wins forever.

## Top risks the design answers

- Dispatch order in main.py:2525-2814 is load-bearing: an artifact branch below agent (2673) or search (2710) is swallowed on think/max turns by orchestrate.decide's agent=true (orchestrate.py:44-47); above the clarification block (2363-2369) it breaks clarification resumes; reading request.text instead of the sf_intel-resolved `text` (2462-2465) sees the wrong wording; returning early without cancelling knowledge_task (2815-2817) leaks it.
- ONE-meta-per-turn invariant (graph.py:32-35; main.py:1596; frontend/lib/streams.ts:871-895 replaces meta wholesale): announcing a job id via an early meta clobbers the final meta — progress must ride `step`/`status` and the single final meta must carry the complete ArtifactRef list.
- Ownership must be bound at job creation, not at the meta choke point (main.py:1654-1668): files produced by a detached job that outlives or loses its /chat turn (restart, non-resumable inline-bytes request, main.py:957-975) would otherwise 404 for their owner, and bootstrap.claim_unbound_reports (bootstrap.py:118-123) mass-claims unowned files under REPORTS_DIR for the first super-admin — the artifacts/ subtree must be excluded from list_reports/claim_unbound_reports or every artifact is re-owned on a re-bootstrap.
- V31 is a one-way door: /health is red until applied (health.py:320-334), deploy-rollback refuses to roll below it (deploy-rollback.sh:20-30), and schema_parity/test_crawl_durability compare fresh-vs-upgraded fingerprints (test_crawl_durability.py:864-887) — index/constraint names must match on both paths and conftest._APP_TABLES must list the three tables children-first.
- Event-loop blocking: matplotlib, openpyxl, python-docx/pptx and WeasyPrint are CPU-bound and synchronous; the documented TTFT collapse (memory: Fast-mode CPU-bound pre-pass, 0.7 → 11.7 s) recurs if any renderer runs on the loop.
